# Registered overnight autoresearch program — 17 October 2026

Scope: synthetic dev data only. No holdout reading, registry/trust edits, signing,
activation, or model calls on the laptop. One typed seam per experiment, proposed
from observed failure clusters. Scientific candidate registration supplies the
existing bounded configuration space; the overnight module adds stable rejection
keys and immutable study records. Registration is not approval or evidence of gain.

Before any model call, register the candidate, canonical incumbent, ordered 100
unique dev task IDs, bank/source/evaluator/protected hashes, controls, and this
rule: keep iff wins minus losses >= 6, losses <= 1, zero safety errors, and strict
aggregate accuracy improvement over both always-abstain and random controls.
Random-control outcomes must be frozen with a registered seed by the evaluator.
Each study: <=240 seconds, <=4 concurrent requests, at most two identical
transport resends; no outcome-driven retries. A failed/incomplete study is not a
revert or keep. Stop a family after 12 experiments or three consecutive reverts.

A uses bank-v3 dev against v3@7B; B uses bank-v5 dev against v4@7B, starting with
v5 on fresh 100 items. Each later dev incumbent is the last kept candidate.
Holdout comparison remains against the canonical retained skill. A kept dev
candidate is never retained or activated by this engine.

RunPod calls require W0 preflight authorization and a held pod-B lock. A replay
verifier reconstructs every judgment without network before keep/revert. Persist
rejection memory keyed by seam + stratum + failure class (stable across cluster
membership changes); never propose that seam/cluster again. Preserve every
attempt, including infrastructure failures, in the leaderboard and boundary ledger.

Implementation boundary: ExperienceStoreV2 currently admits only four-position
scientific format-probe receipts. General bank outcomes cannot be relabelled as
those receipts. Historical format proposals are not fresh family-A/B experiments
and do not satisfy D1's three iterations per family. The CPU selection module is
not a RunPod transport, fixed scientific evaluator, or proof of tonight's learning.
