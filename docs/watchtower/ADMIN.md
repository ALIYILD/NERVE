# Independent administration and notifications

The safety package uses no NERVE runtime imports. `OwnerVerifier` verifies operator-pinned RSA public keys with RS256, exact issuer and audience, subject-to-tenant allowlist, expiry/not-before/issue times, mandatory MFA (`amr=mfa` or an explicitly pinned MFA ACR) and authentication time. Restart operations require MFA authenticated within 300 seconds. The core engine must independently consume each request/approval JTI atomically, reject expired identities, enforce tenant ownership and verify recovery checks. Telegram replies never authenticate anyone.

`create_server(engine, verifier)` binds only 127.0.0.1. No server starts on import. Deploy behind separately administered HTTPS ingress with restricted owner access, request limits and an independent identity provider; never expose the Python server directly. Bearer tokens are accepted only in the Authorization header. Proxy identity headers, cookies and query tokens are not trusted. The portal keeps tokens in its password field, never browser storage. Responses use no-store, CSP, text rendering and no external scripts. Requests have 4 KiB bodies, 5-second socket timeouts and 16 concurrent connection slots. All mutation auditing and replay protection belong to the engine transaction; this presentation layer cannot grant access through a button or URL.

The 15 dashboard panels show supplied evidence and UNKNOWN when absent. They do not invent normal activity. Synthetic demonstrations must supply `synthetic=true`; the engine's timestamp, visibility and coverage gaps remain visible. Audit download and incident recovery actions use the same owner verifier. Token provisioning, production TLS/IdP and real owner MFA are deployment prerequisites, not satisfied by synthetic JWT tests.

`HTTPSDelivery` supports the pinned Telegram Bot API and a configurable transactional email HTTPS endpoint accepting a Resend-compatible JSON message. Credentials are provisioned in regular, non-symlink files, mode 0600, owned by an explicitly approved Guardian/root UID. Files must reside in a Guardian-only directory/secret-manager mount; NERVE must have neither read nor write access to that mount or its parents. This local implementation cannot prove remote administration independence. Email endpoint and sender are operator-controlled deployment settings; redirects are denied, timeout is five seconds and response bodies are bounded. There is no credential discovery and no real send without explicit adapter configuration.

`Notifier.enqueue` returns immediately through a bounded queue. A dispatcher commits an isolated SQLite outbox; separate email and Telegram workers deliver independently with bounded retries, rate limits and durable deduplication on tenant/incident/event/channel. Only reference-oriented allowlisted fields are serialized: callers must provide non-sensitive identifiers and safe dashboard links, not raw evidence, patient text or credentials. Failure records contain no provider exception text. Provider acceptance does not prove the owner read a message. `health()` reports queue/storage loss and exhausted delivery failures; an external monitor must poll it and escalate through another channel. The core incident log is the authoritative reconciliation source for entries lost before queue persistence. Deduplication is durable, but a crash after provider acceptance can cause duplicate delivery; exactly-once delivery is not claimed.

Validation uses locally generated RSA keys, a loopback HTTP portal and injected fake provider functions. No production IdP, email account, Telegram bot, external monitoring account or test credentials were supplied. Actual Telegram/email delivery and production MFA remain blocked pending independently provisioned test infrastructure. No live notifications were sent.

Follow-up adversarial validation rejects explicit delegation (`act`, `may_act`, on-behalf-of) and machine/client-credentials claims even when a token names an allowlisted owner. Allowlist entries must be independently administered human identities; claim filtering cannot establish that operational property by itself. Provider-contract tests intercept urllib transport without network access: Telegram `ok:false`, malformed/oversized payloads and HTTP 429 fail; email requires a nonempty provider message ID and rejects malformed success bodies/HTTP 500. Errors are sanitized before leaving the adapter and never stored in the outbox. Exhausted delivery makes independent health UNKNOWN. SQLite contexts now close descriptors on both transaction success and failure. Eight local tests pass; live delivery remains unverified.
