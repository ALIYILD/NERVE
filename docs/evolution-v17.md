# NERVE Evolution v1.7 — Bounded agent recovery

## Objective

Test whether **evaluated, contextual episodic memory** changes the number
of agent tool attempts needed to recover from a failed initial strategy.
The decision to accept a result belongs to a **trusted independent judge**
and never to the agent's own assertion or recalled text.

## Implementation

`src/nerve_awim/recovery_learning_v17.py` provides
`BoundedStrategyRecovery`, a bounded, local multi-context executor.
It uses registered, trusted Python handlers through NERVE's existing
parallel agent worker pool, with one or two attempts per task.

- No arbitrary code generated by LLMs is executed.
- Unknown strategy IDs in memory are ignored, not interpreted as commands.
- No hidden model-weight changes or retraining occur.
- Held-out tasks NEVER update memory; only explicit, evaluator-backed
  `record_training(...)` calls can add rated experiences.
- A strategy's execution exception is recorded as a failed attempt and
  a bounded alternate may be tried. A **judge exception rejects the entire
  batch** rather than being recast as a negative label.
- Unresolved inputs stay unresolved. Both the memory and non-memory
  variants use identical contexts, tools, judges and retry budgets.

## Three-way controlled comparison

Run the benchmark:

```bash
PYTHONPATH=src python benchmarks/v17_recovery_agents.py
```

Each seeded experiment evaluates three contexts: email cleanup, numeric
sorting, and JSON value extraction. All six handlers are known in advance,
and the program-trained memory uses exactly the same three feedback samples
per candidate before the held-out experiment.

The comparison reports:

1. `no_memory`: an equally capable executor with randomly ordered
   registered strategies, a fixed first choice and one allowed fallback.
2. `memory`: the same executor prioritising the historically
   higher-rated registered strategy before retry.
3. `fixed_correct`: a correctly configured non-learning system with
   the verified first-choice strategy already pinned.

All three get up to **two tool attempts per task**. Three intentionally
unsolvable cases per 27-task batch remain failures for all methods.
First-attempt success, final success, retry recovery and total tool calls
are reported separately. Results are synthetic and do **not** prove faster
real LLM reasoning or real-world adaptive intelligence.

## MCP demonstration

`learn_mcp.py` also exposes `run_bounded_recovery_demo`, restricted to
fixed synthetic data. No user-supplied handler, medical input or
external evaluation code can be passed to the demo.

The following is a local MCP tool invocation, after connecting the
stdio server and installing official MCP 2.x:

```json
{"policy":"memory","train_on_fixtures":true}
```

The demo trains on three fixed internally scored examples, then
evaluates four program-owned tasks (three recoverable, one irrecoverable).
The output lists bounded attempted strategy IDs, counts of completed
and unresolved tasks, and total registered invocations. There is no
production self-repair, clinical device control, robot actuation,
or permission to modify NERVE safety policies.

## Limitations

Agent IDs in the SQLite experience store are a local namespace, not
authenticated identity. The judge callback must be provisioned by
trusted code and must not be constructed from unverified agent output.
Thread workers are not resource-isolated or hard-time-limited.
A well-configured fixed strategy can match memory efficiency, and a
recoverable baseline with equal retry permission can achieve equal
final task success. This study supports **attempt-efficiency** research,
not claims of better general intelligence or clinical safety.
