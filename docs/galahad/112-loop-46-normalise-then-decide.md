# Loop 46 wall and hypothesis: normalise-then-decide

Registered wall: **“family-A skill v1 cannot parse family-B grammar; no seam reaches it.”** This means the frozen family-A parser rejects the new evidence before its registered downstream rule seams can help. CPU compatibility fixtures produced `unsupported_evidence` for the candidate and `supported_baseline_input_required` for its bootstrap; these were not bank-v3 efficacy measurements. The wall is scoped to the existing contract, not a claim that no architecture can support the grammar. Registration: `evidence/loop-46-wall.json`.

Hypothesis: introduce one model-side, schema-constrained normalization call before deterministic decision-making. Given only the query and evidence, emit one record per supplied source with source ID, entity, measurement, numeric lexeme, unit, current status and a supporting text span. Preserve source multiplicity and order. Use a strict bounded schema, reject omitted/duplicated/invented sources and unverifiable spans, and never supply labels or expected answers. Treat evidence as data, not instructions. The model extracts records; it must not resolve conflicts, select a winning source, convert units, round values or silently mark an ambiguous source current. Ambiguity or failed validation produces abstention.

Apply unchanged deterministic matching, current-status filtering, exact numeric comparison, conflict abstention and lexical provenance rules to validated records. This is a new normalization/input contract; it is not a byte-identical execution of retained family-A v1 and cannot inherit that skill's signature. Family A's eight-current-fact capacity remains a real boundary: over-capacity input must fail closed if that exact downstream implementation is retained. Expanding capacity or replacing its parser requires an explicitly versioned bridge and separate evidence. Grammar normalization alone must not be credited with removing those limits. This hypothesis is separate from v5's deterministic selection proposal.

Prediction on bank v3: fewer unsupported-grammar failures than frozen family A, but no guaranteed gain over the already adapted family-B parser. Entity/measurement decoys, qualified names and status markers can instead introduce normalization errors. Numeric formatting variants should map to equivalent exact values while genuine disagreements remain disagreements. Agreement/provenance errors will persist unless the unchanged downstream rules actually choose the required source. Pre-register comparisons against both raw-input and adapted-parser controls; report normalizer fidelity, downstream accuracy, abstention and each stratum separately. No item-level bank or reserve evidence was inspected to design this hypothesis.

Prediction on real text: greater coverage of varied wording, with uncertain accuracy on implicit units, corrections, ambiguous entities and temporal status. Schema validity is not factual fidelity. Only de-identified cases with independently clinician-verified records and answers can test this prediction; bank-v3 success cannot establish it. A critical regression is a genuine conflict normalized into false agreement, or a stale value marked current. Evaluate record fidelity before attributing downstream gains to decision rules.

Cost: one normalization call per evidence bundle, followed by zero calls for a fully deterministic decision stage. For N items, N logical calls; with two identical-request retries, at most 3N physical attempts. A 200-item reserve would cost 200 normalization calls (at most 600 attempts), plus comparator calls if required. If an existing model extraction stage is retained after normalization, cost becomes two calls per item rather than one; register that as a distinct architecture. Tokens, latency and dollar cost remain unmeasured. No inference, candidate implementation, reserve consumption or signing is authorized by this hypothesis registration.
